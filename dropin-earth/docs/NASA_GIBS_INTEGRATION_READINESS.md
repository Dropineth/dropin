# NASA GIBS Integration Readiness

Date: 2026-07-14

Status: **NON-PRODUCTION IMPLEMENTATION UNDER REVIEW - PRODUCTION NOT READY**

Deployment status: **NOT DEPLOYED**

Feature state: **DEFAULT OFF (`CANOPYPROOF_NASA_GIBS_ENABLED=false`)**

## Decision

The read-only NASA GIBS connector is implemented far enough for local security,
database, API, UI, and OpenNext review. It is not ready for production,
institutional reliance, or live NASA synchronization. No named architecture,
security, Earth-science, licensing, or operations approval has been recorded.

No live NASA imagery or capabilities document, production credential, private
key, tenant data, or project location was persisted during implementation or
tests. Test fixtures are synthetic and clearly identify themselves as such.

## Implemented

- Fixed HTTPS endpoint registry for NASA GIBS `best` WMTS/WMS capabilities in
  EPSG:4326, EPSG:3857, EPSG:3413, and EPSG:3031. Callers cannot submit URLs.
- Bounded fetch with timeout, redirect denial, media-type checks,
  content-length and streamed-byte ceilings, strict UTF-8, and defensive XML
  parsing that rejects DTD, ENTITY, XInclude, and extra processing
  instructions. Missing as well as unexpected response media types fail closed.
- Normalized `NasaGibsProduct`, projection, temporal extent, service endpoint,
  and layer-availability records with exact source-byte SHA-256 hashes.
- Explicit current, stale, unknown, and outage semantics. Failed sync preserves
  the last complete snapshot and cannot replace it with partial data. Calendar
  dates, declared recurrence periods, and default-date membership are validated;
  source periods materially ahead of synchronization remain `unknown`.
- PostgreSQL adapter and additive SQL for append-only snapshots, products,
  availability, sync failures, command receipts, audit events, signed-manifest
  issuance/nonces, comparisons, source handoffs, and watches.
- Tenant RLS/FORCE RLS policies for interpretation records and database
  triggers that reject UPDATE and DELETE operations. Project-bearing records
  also require an exact canonical project-to-organization binding at both the
  repository and database trigger layers.
- Current product and availability reads are restricted to the newest complete
  snapshot per endpoint; immutable history cannot resurrect a withdrawn layer.
- Empty-only rollback script that refuses destructive teardown after authority
  records exist.
- Authenticated API routes for status, authorized synchronization, products,
  availability, signed manifests, comparisons, attribution records, source
  handoffs, and event watches.
- Sync command idempotency binds the endpoint, actor, organization, and
  caller-controlled request fields; server execution time does not break an
  otherwise identical transport retry. PostgreSQL advisory locks plus bounded
  serialization/deadlock/unique-conflict retries return the one durable catalog
  to concurrent callers and deduplicate concurrent failure records.
- External signature port and public-key verifier contracts. Manifest payloads
  bind tenant, actor, product root, date, bbox, purpose, expiry, nonce, key ID,
  acknowledgement, and non-endorsement. No signing key is read, stored, or
  generated by production application code. A signer result must verify through
  the configured public-key port before any issuance record is accepted.
- Immutable comparison hashes, one-time manifest nonces, opaque Earthdata/CMR
  handoff references, and watch outputs restricted to observation signals,
  risk candidates, and review tasks.
- Attribution records for comparison reports, screenshot metadata, export
  bundles, and institutional report appendices.
- Low-cardinality metrics and trace contracts for capabilities sync,
  availability lookup, manifest generation, comparison creation, and source
  handoff. MapLibre reports only the first tile/render error per map instance
  to an authenticated product-validated counter without sending URLs or bbox.
- Client-only, `ssr: false` MapLibre/deck viewer on `/terra` with fixed-size
  loading/failure states, catalog/date/projection controls, comparison modes,
  freshness/outage disclosure, constrained Worldview deep links, and
  source-data handoff. Deep links freeze Worldview's documented projection,
  layer, and date parameters.
- Focused unit, API, UI-boundary, and PGlite integration tests covering the
  requested endpoint, XML, projection, date, signature, comparison, outage,
  attribution, proof-laundering, and tenant controls.

## Not Implemented Or Not Proven

- A production KMS/HSM signing adapter is intentionally not composed into the
  API. Manifest issuance therefore fails closed when the connector is enabled
  without one.
- Controlled egress with DNS rebinding, private/link-local IP, TLS trust,
  decompression, retry, and circuit-breaker enforcement is not configured.
- No live NASA sync or tile request was made. Fixture compatibility does not
  prove current upstream compatibility.
- The first implementation deliberately uses the single canonical GIBS host.
  NASA's reviewed guidance states that GIBS does not currently support HTTP/2
  and documents `gibs-a`, `gibs-b`, and `gibs-c` sharding for HTTP/1.1 tile
  concurrency. Alias allowlisting, browser load evidence, and amplification
  controls are not yet approved.
- DescribeDomains is not implemented, so availability remains the bounded
  recent window exposed by GetCapabilities rather than a complete history.
- The browser workbench currently uses day-level date inputs and renders the
  live map preview only for EPSG:3857 WMTS products. Subdaily selection, WMS
  preview, and polar rendering remain explicit follow-on work even though the
  registry and domain contracts preserve those variants.
- Native PostgreSQL evidence is local and disposable, not a managed-service
  migration, least-privilege deployment-role, backup, failover, or production
  policy test.
- Database constraints validate structure, authority binding, immutability, and
  selected roots, but do not independently recompute every application-layer
  NASA content hash. Privileged-writer compromise therefore remains outside the
  current database trust boundary.
- Public-key rotation, KMS outage, signer concurrency, and manifest key-
  revocation operations are not exercised.
- Parser fuzzing, compressed-body attacks, load/soak, tile amplification,
  browser accessibility, visual regression, real outage, chaos, disaster
  recovery, and full end-to-end tests remain open.
- Trace records and tile-failure counters use the connector telemetry port;
  central OpenTelemetry export and production alert rules remain operations
  integration tasks.
- No report renderer or screenshot/export pipeline consumes the attribution
  record yet. The domain/API enforcement contract exists; each future artifact
  producer must be tested before release.
- No NASA representative, accredited verifier, Earth scientist, legal counsel,
  privacy officer, data steward, or platform operator has approved the work.

## Source Limitations

- GIBS serves visualizations generated from science products, not necessarily
  the numerical source measurements.
- Imagery resolution and sensor-native resolution differ. EPSG:3857 imagery is
  resampled from geographic imagery.
- Layer availability differs by projection, service, format, and date.
- `best` may combine product versions and latency classes according to
  provider-coordinated selection rules.
- Product-specific third-party rights may apply even when NASA-led mission data
  are generally open.
- Visual context cannot establish causality, project impact, ownership,
  survival, additionality, permanence, or financial value.

## Freshness Limitations

- Near-real-time describes publication latency, not guaranteed current
  coverage at a requested location.
- Current-day tiles may be empty while acquisition or processing is incomplete.
- WMTS GetCapabilities exposes only a recent bounded period window; complete
  availability requires DescribeDomains.
- WMS may select a nearest available period.
- Synchronization time is never treated as observation or publication time.
- Historical products are intentionally marked stale by the operational
  fourteen-day rule; the reason text notes that age may be expected.
- During an outage, the last valid catalog is marked `outage`, never current.
- A declared future source period is `unknown`, never current. Dates inside an
  interval are accepted only when they align with its supported ISO-8601
  recurrence; this still cannot prove that a tile contains observations.

## Security Findings

1. Exact endpoint-object comparison and a frozen registry reject both arbitrary
   hosts and field substitution after endpoint lookup.
2. XML is bounded and rejects known external-entity constructs, but fuzz and
   decompression tests remain necessary.
3. Signed manifests are fail-closed, tenant/root/date/bbox/expiry bound, and
   replay protected; production signing remains blocked on external KMS/HSM.
4. PostgreSQL rows and audit events are append-only, and interpretation reads
   are tenant-bound. Native PostgreSQL 17 tests exercise exact concurrent
   retries, concurrent fail-soft outage deduplication, FORCE RLS under a fixed
   non-owner role, and mutation rejection. This does not mitigate a privileged
   writer able to insert self-consistent forged rows.
5. Event watches cannot emit proof, ESG, certificate, emergency, funding, or
   token authority states.
6. The browser does not receive arbitrary service URLs or credentials. It
   constructs only a fixed NASA WMTS template from a signed manifest.
7. A server-side open tile proxy was not created.
