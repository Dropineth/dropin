# Accountability regression policy

This increment treats authenticated transport as evidence, not authority to execute, award a contribution, create an entitlement, spend money or issue carbon credits. Real execution remains disabled. Generic protocol code has no child, age, guardian or ecological-credit policy; those belong to separately authorized product scenarios.

The ordinary `npm test` inventory includes the accountability regression files. The existing workspace CI command additionally runs `npm run test:accountability`, and its existing Life++ command wrapper captures the new TAP and JSON receipts. This does not replace the protected release policy or add a parallel release approval. PR-head and merge-candidate receipts are distinct and are never interchangeable.

## Finite attack inventory

| Boundary | Regression and independent oracle |
|---|---|
| Canonical byte ambiguity | Fixed numeric-key bytes and independently computed SHA-256 constants; seeds 0 through 31 cover nested JSON, Unicode and key order. Generic application hashes stay unchanged. |
| Caller-selected weight and collusion | Duplicate source, signer or content cannot accumulate local weight. An authentic local receipt still cannot become protocol authority. |
| Signature/current registry | True Ed25519 positive control; outsider, changed bytes, wrong schema pin, revoked key, stale epoch and expiry after asynchronous lookup fail. |
| Financial/ledger elevation | A signed record containing PASS, ACTIVE or paid fields creates only an unassessed evidence projection. All four product-ledger mutations refuse it. |
| Report forgery or incomplete run | Independently supplied CI runner context, exact target SHA, phase, completed/success state, artifact digest and complete test inventory are required. Missing, neutral, skipped, cancelled, timed-out, wrong-head, stale and tampered results fail. A report cannot authenticate its own runner or success. |
| Mutation sensitivity | Isolated, runnable copies remove duplicate-weight protection, current revocation or authority restrictions. The original control must pass; each mutant must fail its designated assertion. Compilation, module loading, timeout and signal failures do not count as kills. |

The mutation corpus is bounded to three specified substitutions. Copies and subprocesses are local, capped at 20 seconds each and removed afterward; no production endpoints or credentials are used. The deterministic JSON corpus is bounded to 32 seeds. Failures report the seed, mutation ID or exact case. Concurrency schedules, crash points and nonce-consumption mutants for upstream owner adapters are maintained in their own authorized repositories, not copied here.

## Existing broader regression coverage

The previously implemented child-stewardship suites remain the product scenario's security tests: signature, learning, rights, API, privacy, offline, resume, media, draft authorization, restore/checkpoint, agent gateway and rate-limit tests. Native suites already run through the existing PostgreSQL CI command. They cover tenant isolation, current delegation/revocation, control-domain independence, nonce and receipt replay, funds conservation, offline withdrawal, immutable audit and backup restoration. Release/supply-chain tests remain under the existing release-policy and supply-chain runners. This increment does not relabel those tests as tests of external protocol implementations.

Untrusted document or tool content cannot supply a current authority registry, signer qualification, CI runner identity or release approval. There is no new model/tool execution route in this increment. Existing prompt/tool and release-policy boundaries remain applicable; this document does not claim a new autonomous-tool security certification.

## Finding lifecycle

| ID | Reproducer | Fix and verification state |
|---|---|---|
| C01 | Numeric keys produce different legacy and transport bytes | Dedicated transport serializer and explicit identical-byte reference conversion; focused owner and independent tests passed. |
| C08 | Duplicate caller-weight sources or local accepted receipt promoted to authority | Deduplicated local projection; independently current signed transport remains nonauthorizing. Focused owner and independent tests passed. Product adapter and mutation additions require their own final candidate check. |
| RT-RECEIPT-01 | One `A\nB` ID could compare equal to two expected IDs | Strict ID validation plus exact elementwise inventory comparison; deterministic counterexample is in the ordinary test suite. |
| RT-RECEIPT-02 | Artifact success without authoritative runner completion | Independently provided completed/success context required; missing, in-progress and non-success counterexamples included. |

A finding closes only after its reproducer fails against the vulnerable executable behavior, passes against the fix with a legitimate positive control, and independent review/retest is recorded against an exact source fingerprint. Owner green logs alone are not human release approval. Evidence outside the repository records failed attempts, source hashes and final command receipts without modifying historical receipts.

## Scope and unresolved external conditions

No private upstream schema, source or normative specification is redistributed here. Owner-local private adapters use pinned versioned contracts over process transport. Original normative-objective source bytes remain unavailable. Test authority enrollment, synthetic evidence and local PostgreSQL durability do not establish real identity, institutional qualification, evidence truth or production readiness.

The merged main planning document `docs/canopyproof-gods-eye-p0.md` remains a proposed Earth-observation/MRV scaffold. It is not evidence that ingestion, carbon verification or a deployment occurred. Real institutional acceptance and the existing independent human release gates remain separate.
