# Fixed synthetic media pipeline

The isolated `SyntheticChildMediaService` processes two server-owned generated raster fixtures. It accepts fixture IDs, never caller-provided files, URLs, camera input or real child photographs. Public real/free media uploads remain unavailable with HTTP 503. This service is not mounted in production.

`media.ts` decodes PNG/JPEG with Sharp, rejects animation, trailing/concatenated containers, malformed images and oversized inputs, bounds decoded pixels and output size, applies orientation, converts pixels to RGB and emits a fresh PNG without EXIF/ICC/private metadata. Exact source hashes, dimension-bound pixel hashes and two perceptual hashes support conservative duplicate flags. These flags are heuristics, not evidence of fraud or environmental outcomes. Media remains E0 and cannot mint contributions, rights or funds.

`child-stewardship-media.sql` binds each source and every output hash/dimension to an immutable migration-owner-provisioned manifest. Actual bytes live in the privacy inventory as source, derived and index objects. Quarantine blocks family reads. A separate restricted reviewer login and a different actor/control domain must record an exact sanitized digest before family access. The fixture review is labelled `synthetic_role_separation`; it does not establish independent human acceptance. Metadata stripping is not face, address, audio or other sensitive-content classification.

Current session generation, actor, consent, assignment, task and database scope are checked after acquiring the session lock, using actual database time. Read policies enforce current principal and purpose, exclude raw/index bytes and prevent expired authority from reading derived bytes. Service readiness rejects owner/superuser/BYPASSRLS, role membership, mixed scopes and owner connections using SET ROLE. Native tests use independent ephemeral LOGIN identities in a disposable local database; these tests create no production roles or credentials.

Purpose deletion removes actual source, sanitized and index bytes and profile-linked media metadata through the existing privacy worker. Minimal immutable review digests and canonical replay hashes remain. These records do not authorize retention of source images. External processors, backups outside this adapter, real-media protection/classifiers and actual human review remain gated and unconfigured.

Validation: `tests/unit/child-stewardship-media.test.ts` exercises actual decoding, EXIF stripping/orientation, malformed containers, byte/pixel limits and resizing (6 tests). `tests/integration/child-stewardship-media.integration.ts` exercises actual PostgreSQL storage, quarantine, digest/domain separation, forged-manifest rejection, restricted login/readiness, stale generations, waits across actor/task/role expiry, duplicate flags and byte deletion (9 tests including parent test). Run with the repository pinned Node environment and the explicitly disposable local PostgreSQL test configuration. No test claims deployed or external acceptance.

Apply the media migration after base, authority and privacy migrations (resume migration supplies generation checks). Rollback pauses ingress/review while retaining inventory, suppression, audit and replay hashes; the companion rollback file intentionally does not destroy data or invent role approvals. Dependency upgrades require regenerating and independently reviewing deterministic fixture manifests if emitted bytes change.

When the optional restore module is installed, ingress, review and reads require the shared fresh external checkpoint provider under the current session lock. Missing or stale authority returns unavailable. Restored-session media ingress remains unmounted; it must additionally consume the same fresh per-draft authority before any future upload route is enabled.
