# Life++ collaboration world: ten-scale production scope

Status: application integration scope and implementation candidate. This document
does not activate a protocol authority, a production route, enrollment, payments,
robot actions or a public spatial data release.

The product is a multiscale collaboration world: real spaces and physical objects
are connected to accountable CAI participants, causal interaction history, and
functional organizations whose claims can be examined. CanopyProof is its
environmental evidence application; child participation is one CanopyProof
module. Life++ HERE and other applications can use the same organization view
without inheriting the child module's account or financial authority.

## 1. Ten enterable functional scales

These are functional organization levels, not ten spatial dimensions, ten chains,
ten permission ranks, or ten claims of deployed capability.

| Scale | Functional meaning | Evidence required before a production function claim |
| --- | --- | --- |
| Single cell / 单细胞 | One canonical CAI identity | Current identity, accountable controller, capability and delegation boundaries, inputs/outputs and historical references |
| Organization / 组织 | A recurring collaboration around a shared objective | Actual member set, repeatable responsibilities, interaction history and shared input/output boundaries |
| Organ / 器官 | A composite offering a callable, testable function | Versioned function contract, exact membership, acceptance evidence, external dependencies and exception handling |
| Functional system / 功能系统 | Several functions sustaining a class of tasks | Dependency and scheduling rules, resource reservations, feedback, failure containment and recovery evidence |
| Organism / 单个生命体 | A whole service-delivery collaboration | End-to-end acceptance, resource constraints, system state and responsibility for external delivery |
| Population / 种群 | Multiple independently accountable similar service entities | Comparable capability evaluations, independence evidence, shared-resource limits and supported assistance |
| Ecosystem / 生态 | Different entities and environmental resources in an interdependent network | Supply/demand, competition, conflict, resource cycles, external effects and failure propagation |
| Planet / 行星 | Geographic and federated domain aggregation | Explicit coverage, domain boundaries, lawful disclosure and independently attributable source records |
| Galaxy / 星系 | Discovery and interoperability across larger domains | Conceptual in this integration version; future adoption needs actual domain, communication and interoperability evidence |
| Universe / 宇宙 | Discovery across federations and rule systems | Conceptual in this integration version; no assertion of universal coverage, authority or a common governing entity |

Functional organizations are distinct from a registered legal organization. A
tree is a physical entity, not automatically a CAI. A CAI observing the tree is
a separate identity. A single CAI can belong to multiple functions, but its
identity, capacity, budget and governance control source must not be multiplied.

## 2. Preserve independent axes

1. **Functional scale** determines which collaboration and responsibility are
   being examined.
2. **Infrastructure partition** keeps existing AHIN Cell/Field/Region/Planet
   identifiers. An infrastructure Cell can contain many CAIs; it is not the
   single-cell functional level. A functional planet is not a new infrastructure
   partition or a global authorization root.
3. **Physical and display data** have their own objects, local coordinate frames,
   source geometry, assets and LOD. Gaussian/point counts are display quantities.
   Changing LOD cannot change CAI identity, membership, responsibility or approval.
4. **History H** refers to authenticated causal history and versions. Physical
   capture time describes when a source observation was acquired. Display
   interpolation is presentation. None of these substitutes for another.
5. **Readiness and evidence class** remain separate from scale. A conceptual
   universe node cannot make a local demonstration globally operational.

The view uses a membership DAG. Non-membership dependency, competition, shared
resource and conflict relations form a separate graph and can contain cycles.
Hierarchy does not grant authority. Zooming out never creates a permission,
removes a dispute or converts a source-referenced claim into verified truth.

## 3. Responsibility across the full stack

| Component | Responsibility | Boundary retained |
| --- | --- | --- |
| CAI | Identity continuity, capability/delegation and accountable control | A stable identity is not a private key, device, Gaussian or account balance |
| AHIN | Active hashing interaction, membership, challenge and relevant responsibility records | Application read models cannot mint official membership or approval |
| PoCC | Cognitive Canxian consensus and its canonical evidence/verdict contracts | Application hashes and tests do not create a protocol verdict or re-prove the theory |
| ChainRank | Contextual responsibility routing based on its defined theory and validated inputs | Ranking cannot override authorization, revocation, independence or an open challenge; no substitute algorithm is introduced |
| Account execution | Action-specific grants, role-constrained approvals and execution-time checks | Cognitive accountability multisig does not automatically confer wallet, custody or robot control |
| MPC / TEE | Cryptographic control separation and assessed execution evidence where selected | Neither establishes a real person's informed intent or physical-world truth by itself |
| Permissioned ledger / federation | Persistence, scoped disclosure, finality and domain interoperability | Ledger acceptance is not physical verification; membership is not blanket data access |
| Spatial world | Authorized navigation of actual assets, semantic nodes and evidence panels | Appearance, geometry, function and current authority each retain their own evidence |
| Application modules | CanopyProof environmental records, child participation, HERE services and future domains | Each has separate lawful purpose, operating ownership, acceptance and execution policy |
| Operations | Release, monitoring, keys, incident response, backup, restore and capacity | A healthy page or container is not proof that end-to-end authority is connected |

Existing upstream protocols remain authoritative. Integration must use approved,
versioned exported contracts, conformance vectors and pins. Do not copy private
upstream source into this repository or relabel application JSON as official
AHIN signing bytes. The projection added here is original application code.

## 4. Formation is an evidence-bound claim

A composite has an actual member set, function contract, collaboration history,
responsibility boundary, resource constraints, recovery and exit rules. A
reference to an assessment must bind the current member commitment and function
version. A changed member set invalidates that binding. Cosmetic clustering,
message volume and synchronized movement are not formation evidence.

Production evaluation must answer: what function; who participates; what improves
against a stated baseline; what happens under disturbance; when to change or
dissolve. The projection carries references and limitations. It does not perform
these evaluations or claim their conclusions independently verified.

Aggregation computes distinct CAI membership from actual supplied relationships.
Open critical challenges, revocation, degradation, conflict and resource issues
remain visible at every affected ancestor. A majority of completed low-risk
tasks cannot hide one unresolved high-responsibility task. Shared CAIs remain one
identity. Resource commitments require a separate reservation authority; this
projection does not sum shared capacity into invented available resources.

Membership and spatial mapping coverage refer only to the supplied bounded
snapshot. Global population, reconstruction coverage and online concurrency
remain unknown unless independently measured. A hash is an integrity commitment,
not anonymization, authority, evidence completeness or measurement accuracy.

## 5. Authorization, withdrawal and recovery across scales

The account/execution boundary must bind the same intent, object, action, domain,
policy version, current consent/capability epoch, nonce and expiry across proposal,
approvals and execution. Parameters changed after approval require a new approval.
Current authority is checked where a side effect occurs, including queued work.

Policies name required roles and actual control-domain independence. A person and
their digital twin are one authority source. Multiple CAIs controlled by the same
authority cannot manufacture independent votes. Digital twins remain within
delegation scope; no agent expands its own grant. Selecting a larger organization
or world scale does not widen permission.

Optional consent withdrawal is not contingent on a majority agreeing to permit
withdrawal. Freeze and revoke affect specified capabilities, not the erasure of
historical accountability. Recovery must not revive revoked grants, consumed
nonces or obsolete consent. Offline agents cannot learn new revocations
instantaneously: permitted offline actions, lease lifetimes and safe stopping
conditions must be explicit and measured.

Child safety, already-established benefit rights, complaints and basic-service
continuity are separate from optional participation. Institution roles for UN
agencies, UNICEF, Breakthrough Energy and national/local authorities remain
prospective until explicit agreement and real authority enrollment. No such
organization is assigned a signer or endorsement by this integration.

## 6. Production admission by profile

The machine-readable [production profile](../../integrations/collaboration-world-v1/production-profile.json)
lists required evidence categories. It is a requirements manifest, not a release
approval or a callable policy bypass.

| Profile | Additional evidence before activation |
| --- | --- |
| World read | Current authenticated source adapter, object-level read authorization, history/rollback protection, deterministic bounded projection, live UI integration and operational acceptance |
| Physical evidence | Authorized real capture, provenance, coordinates/scale and calibration, CAI-to-object mapping, separate visual and geometry QA, safe asset delivery and deletion/revocation controls |
| Child participation | Real caregiver/representation authority, age-appropriate child voice, independent safeguarding/complaint path, local data responsibility, tested withdrawal and recovery; no public child directory |
| Robot action | Authenticated current command authority, robot-local safety controller, permitted offline behavior, collision/localization evidence and field acceptance |
| Benefit or asset execution | Separate action/role policy, eligible entitlement and recipient verification, actual custody/settlement integration, idempotent external receipts and accountable recovery |
| Federation | Domain agreements, explicit trust and rule mappings, data-residence/disclosure controls, cross-domain revocation/failure handling and measured capacity |

All active profiles share threat-model, independent review, pinned artifacts,
approved deployment target, rollback/restore, monitoring and incident ownership.
Evidence is recorded per domain, function, version and profile, not as one global
"production" boolean. No single world-view test opens a child account, certifies a
carbon credit, authorizes a robot or transfers an asset.

## 7. Delivery sequence and exact limits of this increment

1. **Implemented candidate:** bounded ten-scale graph projection; separate
   physical/infra/display/history axes; computed membership; issue propagation;
   formation-reference validation; synthetic conformance tests.
2. **Next source integration:** connect the accepted external AHIN read-admission
   interface, including exact source and policy pins, current issuer/registry,
   authenticated history and independently current antirollback evidence. A
   request-supplied `verified` flag, replayable checkpoint or local mirror cannot
   supply that authority. No authenticated mode is implemented here.
3. **World interface:** integrate authorized real assets into the existing
   spatial/collaboration/organization views, with progressive loading, object
   picking, task/evidence panels, accessible alternatives and history replay.
   This increment does not implement a renderer or ship a new decorative globe.
4. **First physical closure:** one authorized CanopyProof unit and one real
   observation, correction and acceptance cycle; test member failure, contradictory
   evidence, withdrawal and recovery before claiming a functional organ.
5. **Replication and federation:** a second physical unit, then a HERE service
   domain and independently operated domains. Measure cost, data access,
   availability and revocation latency under the actual workload.

There is no supported claim here of hundreds of billions of online agents, a
global 3D reconstruction, a live galactic domain, accepted institutional signing
authority or independently proved physical outcomes. These remain separately
testable scope and capacity questions, not labels inferred from ten-level UI.

The original CanopyProof product, its existing child module and valid workflows
are retained. This scope broadens the shared world model without replacing the
environmental platform with a child-only site or a general-purpose wallet.
